# NeoBuzz Live

NeoBuzz Live is a fork of [ReBuzz](https://github.com/wasteddesign/ReBuzz) (MIT, by WDE and the ReBuzz contributors). The app is NeoBuzz Live wherever it shows: its windows, menus and dialogs, the Mac app `NeoBuzz Live.app` and its disk image, the Windows `NeoBuzzLive.exe` and its zip, the MCP server `neobuzz-live`. The code keeps ReBuzz's names (`ReBuzz.sln`, the `ReBuzz.*` projects, namespaces and assemblies), its file formats, the machine names songs save ("ReBuzz Audio In"…) and its settings folders, so songs, settings, machines and upstream merges carry over. ## Building the package

Needs Windows with:

- Visual Studio 2026 with the **Desktop development with C++** and **.NET desktop development** workloads. Visual Studio 2022 works too; `build.ps1` then builds the C++ projects with the v143 toolset instead of v145.
- .NET 10 SDK (x64)
- git (for submodules)
- The **VC++ 2010 SP1 x64 redistributable** (`msvcr100.dll`), which upstream's `bin64\dsplib.dll` imports. Without it no 64-bit native machine loads. `build.ps1` copies it into the package's `bin64`, so people using the zip don't need it.

Then:

```powershell
.\build.ps1                      # full build -> dist\NeoBuzz-Live-<date>-<sha>-x64.zip
.\build.ps1 -SkipCore            # rebuild machines + package only
.\build.ps1 -Version 0.1.0       # custom version label
.\build.ps1 -SkipNativeMachines  # leave out the 17 classic natives built from source (built by default)
Get-Help .\build.ps1 -Detailed   # all options
```

The zip contains `NeoBuzzLive.exe` (the app; its assembly stays `ReBuzz.dll`), `README-FIRST.txt` (runtime prerequisites, how to start it and connect an agent), `GEAR-INVENTORY.txt` (every machine and where it came from) and `BUILD-INFO.txt` (machines that failed to build, if any).

No Windows machine at hand? Run the **Fork package** workflow from the Actions tab and download the zip from the run.
