# Rules

These are the rules of the project that a new machine must follow. [AGENTS.md](../../AGENTS.md) is the full text, and it wins if this page and it ever disagree. The rules about **how work is planned, claimed and merged** (issues, scope, branches, reports) are in AGENTS.md and [`docs/tasks/README.md`](../tasks/README.md); this page covers the rules about the **machine itself**.

## Clean break

NeoBuzz Live opens and saves only `.nbl` songs and runs only Neo machines and the internal ones. Write **no code for old Buzz songs, formats or machines**: no importer, no loader, no fallback for a legacy file.

## Clean room

A new machine and a new model come from **published literature and our own DSP**: papers, textbooks, standards and our own measurements.

- Never copy code, parameter tables or presets from another product or from a legacy machine.
- Do not open another product's or a legacy machine's sources to see how it did it.
- If you are unsure where an idea came from, say so in the task's issue before you build on it.

A machine's guide and its README name the published sources it was built from.

## No trademarked names

No brands, product models or artists in UI text, machine names, preset names, parameter names, guides, comments you ship or docs. **Name a sound by what it is**: "Tape", "Spring", "Ladder filter", "Warm bus", never a product, a model number or a person.

This applies to this documentation too. A preset called "Swell — Slow Breath" says what it does; a preset named after a famous instrument or a musician does not belong. When you are not sure whether a word is a trademark, choose a plain one.

## Real units and versioned state

- Parameters are in **real units** (dB, Hz, ms, per cent, cents), written in `Params.def` and generated by `tools/gen-machine-params.py` ([params.md](params.md)).
- Presets are in `Presets.txt` and generated by `tools/gen-machine-presets.py`.
- **State is versioned.** New parameters are **appended** at the end, so that saved songs, presets, MIDI maps and automation load and sound the same ([state.md](state.md)).

## Every effect has Mix and Amount

Every effect has **Mix** (dry against wet, latency-compensated) and **Amount** (the strength of the effect, 0 to 200 %, where 100 % is the settings as they are and 0 % is bit-exact dry), through the shared helper `FxStage` ([tutorial, step 5](tutorial.md#step-5-mix-and-amount)). Only meters and analysers, which pass audio unchanged, are exempt.

## Presets

Presets are **clearly audible** at first listen, on full-scale material, and **clearly different from each other**. A subtle preset is a bug. The tutorial's preset test shows how to check both: it renders every preset, requires the level to move by at least 3 dB and requires every pair to differ by a stated margin. The project owner approves the sound before the machine merges ([audio-thread.md](audio-thread.md#listening-packs-and-the-click-detector)).

## The audio thread

0 bytes allocated per block, no locks the UI can hold, no denormals, and every parameter smoothed, so that there is no zipper noise above -60 dB under automation. [audio-thread.md](audio-thread.md) says how, and how each is tested.

## Licences

- **Training data** for any model is **CC BY or CC0 only**.
- **Never commit model weights, third-party audio, rendered audio, features or evaluation data.** A listening pack stays on the computer, in a folder that Git ignores.
- Do not add a dependency or a sample whose licence you have not checked.

## Files

Keep each file's **byte-order mark and line endings** as they are. A generated file is changed only by running its generator.

## A new machine needs all of this

A new machine is a folder under `Machines/`, with the Portable and Studio projects, the solution entry, the manifest, the catalogue and profile entries, factory presets, an editor in the house style, an agent guide within its token budget, unit tests for every gate in its brief, and a row in `docs/specs/machines.md` and in `FORK.md`. [The tutorial's last step](tutorial.md#step-11-what-a-real-machine-adds) lists them; [AGENTS.md](../../AGENTS.md) section 4 is the rule.
